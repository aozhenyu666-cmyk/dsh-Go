## 1. 一句话总览

大肥鱼不是一个"聊天机器人 + 定时器"，而是**三层进程、五个插件、四份本地库**互相咬合的一套东西：

```
┌─ Flutter（Dart，App 界面层）───────────────────────────────┐
│  主动交流页 / 设置 / 聊天 / 人格编辑                         │
│  只做两件事：搬数据、显示。不做任何决策（"kernel 决定，Dart 只转"）│
└──────────────┬─────────────────────────────────────────┘
               │ MethodChannel / EventChannel（见 §4 表）
┌──────────────▼─ Kotlin（原生，Android 侧）──────────────────┐
│  loop/core      主动交互内核（Coordinator 状态机 / 调度器）    │
│  loop/proactive Android 适配器（闹钟、通知、浮层、TTS、闸门）  │
│  loop/*         无障碍前台读包名、行为拦截、专注监督           │
└──────────────┬─────────────────────────────────────────┘
               │ Dart 带 cookie 转发 HTTP（App 不直连引擎）
┌──────────────▼─ Node 引擎（proot rootfs 里跑）──────────────┐
│  DSH_HOME=/root/.dsh                                       │
│  五个随包插件：relationship / feiyu-mood / fish-strict /     │
│               go-memory / go-companion                      │
│  DSH 自己的 agent 会话（大肥鱼本体就在其中一个会话里）          │
└──────────────┬─────────────────────────────────────────┘
               │ 读写的本地文件与 SQLite
┌──────────────▼─ 持久层（全在 /root/.dsh 下）────────────────┐
│  companion/{config.json, topics.json, ledger.jsonl}         │
│  fish-memory/fish-memory.sqlite（记忆权威）                  │
│  relationship/relationship.db（线程/承诺/人格表）             │
│  feiyu-mood/state.json（心情）                              │
│  loop/proactive/{coordinator.json, scheduler.json, ledger.json}（App 侧）│
└─────────────────────────────────────────────────────────┘
```

**关键设计取向（决定了所有细节）**

1. **只有一个主动调度器**：`dsh-go-companion` 负责"什么时候开口说什么"。老的 `dsh-speak-up` 故意不部署（两个调度器会抢同一个声音）。
2. **决策与执行分离**：插件决定"发不发、发什么内容、什么渠道"；手机只负责"能不能发、怎么显示"。
3. **内核不碰网络，Dart 不碰决策**：Kotlin 内核要调插件时，命令交给 Dart，Dart 用它持有的引擎 cookie 转发 HTTP，再把原始答复原样交回。
4. **账本即状态**：回合、拍数、阶梯级别全部从账本重建，进程重启不丢、也不多存一份状态。
5. **诚实的失败**：判球失败退回规则、语音念不出来退回通知、插件没装就当作没有——绝不假装成功。

## 2. 进程与容器

| 层 | 是什么 | 关键事实 |
|---|---|---|
| APK | Flutter + Kotlin 同一个 app | 包名 `io.github.ccch1mneyyy.dsh_app` |
| Kotlin 进程 | 常驻；闹钟、无障碍、通知、浮层、TTS | `ProactiveRuntime` 是 **object 单例**，主线程 |
| Node 引擎 | 跑在 proot 的 rootfs 里 | `DSH_HOME=/root/.dsh`；日志 `files/runtime/logs/dsh.log` |
| 插件目录 | 引擎启动时由 APK 写进去 | `files/runtime/rootfs/opt/dsh-app/plugins/`（每次启动重写，手改不保留） |
| DSH 会话 | 大肥鱼本体 | 目前目标会话 `session-6ec5217f-0b7f-4f34-8320-f69a160a76e1` |

**为什么引擎时区是个坑**：引擎进程跑在 `TZ=GMT`，而"安静时段""每日重置"都该按**手机墙上时间**算。所以手机请求里带 `timeZone`（`ProactiveRuntime.kt:270` 用 `TimeZone.getDefault().id`），插件不传时退回 `Asia/Shanghai`。

## 3. 五个随包装的插件

部署清单在 `app/android/.../runtime/BuiltinPluginGuest.kt:44-123`（`PLUGINS`），每个插件列出要写进设备的文件；加功能必须同时往这里加文件名，否则真机 `MODULE_NOT_FOUND`（我们踩过）。

### 3.1 `dsh-go-companion` —— 唯一的主动发球中心（本轮改得最多）

- **定位**：从话题池里挑话题、判断该不该开口、组织 prompt、记账本、给出发球类型与回合。
- **数据**：`companion/config.json`（配置）、`companion/topics.json`（话题花园）、`companion/ledger.jsonl`（账本，一行一条事件）。
- **对外 HTTP 路由**（前缀 `/dsh-go-companion/v1`）：
  | 路由 | 方法 | 作用 |
  |---|---|---|
  | `/request` | POST | 手机说"该发一球了"，插件挑话题、拼 prompt、推给 agent 会话 |
  | `/result` | GET | 长轮询取生成结果（accepted→claimed→generated） |
  | `/cancel` | POST | 撤回这一球（文本晚了就丢掉） |
  | `/plan` | POST | **只回答"下次什么时候能开口"**，一次调用零模型 |
  | `/outcome` | POST | 手机报展示回执：delivered / displayed / dismissed / replied / substantive |
  | `/config` | POST | 改配置（含人格卡、模式、语音） |
  | `/status` | GET | 给设置页看：配置、账号、话题、今日计数、阶梯状态 |
- **对外工具**：`companion_topic`（让模型能主动记/改话题）。
- **源码分区**：`index.js`（装配与路由）、`plan.js`（该不该发，纯函数）、`prompt.js`（拼 prompt）、`serve.js`（发球类型骰子）、`judge.js`（判球）、`rally.js`（回合/拍数）、`stock.js`（套话相似度）、`silence.js`（漠视阶梯/安静指令/语音指令）、`persona.js`（人格卡与模式）、`classify.js`（规则兜底分类）、`tz.js`（时区）、`ledger.js`、`garden.js`、`topics.js`、`context.js`、`core.js`（Desk：请求状态机）。

### 3.2 `dsh-go-relationship` —— 关系内核（线程 / 承诺 / 人格表）

- **定位**：跨会话的关系账本，本地 SQLite，不读屏、不联网。
- **数据**：`relationship/relationship.db`。
- **工具**：`relationship_status` / `_observe` / `_commit` / `_correct` / `_check` / `_nightly` / `_resolve`。
- **人格表**：`persona` 表，字段 name / values / non_negotiables / voice / own_interests / boundaries / version / updated_by。**默认值就是大肥鱼的人设**（见 §10）。
- **重要事实（缺口）**：`getPersona()` 只在 `engine.js:29` 用来"没有就写一份默认值"，**全插件没有任何一处把 persona 拼进给模型的 prompt**。也就是说这张人物卡目前是**存着但没被使用**的数据。

### 3.3 `dsh-go-memory` —— 记忆权威

- **定位**：手机上的 SQLite 是唯一权威，`fish-memory.sqlite`；没有 `node:sqlite` 时退到 JSON。
- **工具**：`remember` / `memory_search` / `memory_correct` / `memory_forget` / `memory_topic`。
- **注入方式**：每轮按当前这句话检索相关几条，塞进 `systemPrompt.context`，位置在对话末尾——**刻意不破坏系统提示词的前缀缓存**。
- **四件事**：存（带范围/重要度/钉住/过期）、取（每轮检索）、话题（还没聊完的事单独存）、看（原生记忆面板：搜索/钉住/纠正/忘掉/导出）。

### 3.4 `dsh-feiyu-mood` —— 心情

- **定位**：心情不是关键词硬猜，而是每轮聊完用 DSH 自己的模型判涨跌。
- **数据**：`feiyu-mood/state.json`（可多份、可绑多会话、可按工作区）。总心情 0~100，基线 70，**没有底线**，随时间衰减回稳。
- **六根情绪**：开心 / 踏实 / 甜 / 心疼 / 担心 / 吃醋。
- **两条硬规矩**：心情下降**永远**因为"心疼她/担心她"，绝不许因为"她惹我生气"；注入从"每轮带一句状态"改成"一次变化只说一次，说事不说调"（每轮重复会变成背景音，把人定死）。
- **和 companion 的交集**：companion 每球读 `feiyu-mood/state.json` 取当前 mood 塞进 prompt。

### 3.5 `dsh-fish-strict` —— 严格模式检查器

- **定位**：用户明确开启严格模式后，按固定间隔发"监督事件"，不掷骰子、不抢 companion。
- **数据**：`fish-strict.json`。
- **提问走 DSH 自带的 `ask_user_question`**（已有 App 外宠物气泡/通知/单选/自填），关掉卡片不算完成。

## 4. 手机 ↔ 引擎：两个方向的通道

### 4.1 Dart ↔ Kotlin（MethodChannel / EventChannel）

| 通道 | 方向 | 用途 |
|---|---|---|
| `dsh/proactive` | 双向 method | 主动内核：status / setConfig / receipts / tickNow / userActivity / agentSessions / agentHttp |
| `dsh/proactive/agent` | Kotlin→Dart event | 内核发来的 agent 命令（request / poll / cancel） |
| `dsh/loop` | 双向 | 触发测试、无障碍事务流 |
| `dsh/phone` + `/events` | 双向 | 前台包名、停留时长、亮屏、充电、任务/问句占用 |
| `dsh/runtime` + `/events` | 双向 | 引擎进程生命周期 |
| `dsh/notify` + `/taps` `/actions` | 双向 | 通知与点击 |
| `dsh/voice` + `/events` | 双向 | 语音输入（录音，不是朗读） |
| 其余 | — | `dsh/intercept`（行为拦截）、`dsh/performance`、`dsh/media`、`dsh/update`、`dsh/native-media` 等 |

**注意**：已有 `dsh/voice` 是**语音输入**（录音上传），和本轮做的**朗读（TTS）**不是一回事。P4 之前代码里没有任何 `TextToSpeech`。

### 4.2 Kotlin ↔ 插件（HTTP，经 Dart 转发）

- 内核只发命令，`AgentPort` 三个 op：`request` / `poll` / `cancel`。
- 一次性读配置/会话走 `fetchPluginRoute(...)`（`ProactiveRuntime.kt:320`）：`GET` 走 poll op，`POST` 走 request op，12 秒超时，`status 0` 表示"没拿到答复"（刻意区别于 HTTP 错误）。
- 路由前缀常量在 `AgentWire.PREFIX`。

## 5. 一次主动发球的全链路（核心工作流）

这是整套东西的主干，按实际发生顺序：

1. **闹钟响**：`WakeAlarm` 唤醒 `ProactiveRuntime.tick()`（只有一个闹钟，没有第二个定时器）。
2. **刷新闸门**：`applySwitches()` + `c.setGate(gate())`。`gate()`（`ProactiveRuntime.kt:489`）读手机真实状态：功能开关、DSH 是否在跑任务、是否有问句开着、是否在系统敏感页、亮屏、解锁、无障碍连通、通知允许、**是否该念（speech）**。
3. **调度器决策**：`ProactiveScheduler.evaluate()` → `Fire` 或 `Wait(reason)`。
   - `Wait` 时立刻 `consultPlanSoon()`：问 companion 下次什么时候能开口，把**唯一的闹钟**挪到那个时间点。
   - `Fire` 时先 `consultPlanSoon(force = true)`（P4 新增），让"这一球该用什么渠道"在发球前就是新的。
4. **提交事件**：`coordinator.submit(EventRequest)`。事件进优先队列，可以 merge（同 dedupeKey）或 drop（队列满）。
5. **挑事件**：`activateNext()`——**`gate.surface() == null` 时直接不激活**（一个 token 都不花）。这就是"锁屏时什么都不发生"的根源。
6. **要文本**：`Command.RequestAgent` → Dart 转发 `POST /request` → 插件挑话题、掷骰子定发球类型、拼 prompt → 推给 DSH 会话 → 202 accepted。
7. **长轮询**：`GET /result` 拿到 generated 文本（或 failed/cancelled）。
8. **判新鲜**：文本超过 `replyFreshMs`（2 分钟）就作废，不显示。
9. **决定渠道**：`Coordinator.advance()` 的 READY 分支（`Coordinator.kt:331-352`）：
   - 换渠道只对 `SCHEDULER` 来源那一球生效；
   - 上一次那个渠道失败过（`avoidActivity`）就退回通知；
   - 渠道优先级：**语音（P4）> 浮层 > 通知**。
10. **执行呈现**：`ProactiveRuntime.run(Command.Present)`（`:387`）：
    - `ACTIVITY` → 先抢 `VisibleSurface` 名额（同一时间只允许一个可见面），再 `ProactivePageActivity.start`；
    - `NOTIFICATION` → `notificationPort.post`；
    - `SPEECH`（P4）→ `TextSpeaker.speak()`，念完把渠道还给屏幕。
11. **回执回流**：表面报 `Posted` / `Shown` / `Acked` / `Answered` / `Dismissed` / `Failed` → `coordinator.onSurface()` 推进状态机 → 同时 `reportOutcome()` 把 `delivered` / `displayed` / `dismissed` 写进 companion 账本。
12. **人的回球**：插件监听 `session/event` 的 `user/message`（且来源是 `user`，插件自己注入的不算）→ 判球 → 写 `replied` / `substantive`。
13. **记账与学习**：账本 + 话题花园（`nextEligibleAt`、`done`、`attempts`）+ 阶梯状态一起更新；下一次 `/plan` 就按这些回答。
14. **安静与切换**：他说"安静一小时""今天别找我""进入教练模式 2 小时""开语音""别念了"——**全部在 `session/event` 里用正则直接判，不花模型调用、不占工具**，直接写 config + 记一条事件。

**状态机（App 侧内核）**

```
QUEUED → AWAITING_AGENT → READY → PRESENTING →（浮层）SHOWN → CLOSED
                                    │  （通知/语音）DELIVERED，永远不会"看到"
                                    └→ DSH 要屏幕时撤回，退回 READY
```

`Stage` 七态：`QUEUED / AWAITING_AGENT / READY / PRESENTING / DELIVERED / SHOWN / CLOSED`。
`Outcome` 十一态：`RESPONDED / DISMISSED / TIMEOUT / CANCELLED / YIELDED / EXPIRED / MERGED / DROPPED / UNAVAILABLE / FAILED / ABANDONED`。
`Engagement`（调度器唯一学习来源）：`RESPONDED / DISMISSED / ACKED / IGNORED_SEEN / UNCONFIRMED / NOT_DELIVERED`。

> 关键在于：**"显示出来"不能证明"他看到了"**。只有他点「我看到了」才开始计回应窗口；窗口跑完没回才算 `IGNORED_SEEN`。

## 6. 每一球的 prompt 里到底装了什么

`prompt.js` 的组装顺序（这是"大肥鱼为什么听起来像大肥鱼"的现场）：

1. 硬规矩：不罗列背景、不提"事件/系统/主动"、不调用工具、不以提问凑数；
2. **先亮观点**再问（任务书要求"先亮观点"）；
3. 这一球的**类型规则**（六种之一，见 §8）；
4. **套话自查**：写之前先问自己这是不是谁都能说的话；上一球是套话就原样打回；
5. **人格卡 + 模式行**（`personaLines()`，空的部分不硬凑）；
6. 当前话题 + 补充 + 话题类型规则 + 上次聊到哪；
7. 少量事实/经历（来自 fish-memory）；
8. 心情、承诺、上次回应判词；
9. 没接球时的"上次我叫了你两次，你在忙什么"这类素材。

## 7. 账本：整套系统的"血液"

### 7.1 companion 账本（`companion/ledger.jsonl`，一行一条）

| 类别 | state 取值 | 谁写 |
|---|---|---|
| 请求流转 | `accepted` / `claimed` / `generated` / `failed` / `cancelled` | Desk（插件内部） |
| 展示回执 | `delivered` / `displayed` / `dismissed` | 手机 → `/outcome` |
| 判球 | `replied` / `substantive` | 插件判球后 |
| 超时未回 | `none` | 插件（2 小时窗口） |
| 用户指令事件 | `muted` / `mode` / `voice` | 插件（正则识别后） |

每条可带：`requestId`、`sessionId`、`topicId`、`topicKind`、`serveType`、`rallyId`、`shot`、`silence`、`stock`、`at`、`text`、`answer`、`failure`、`cold`。

### 7.2 App 侧三本账（`files/loop/proactive/`）

| 文件 | 内容 |
|---|---|
| `coordinator.json` | 快照：活动事件、队列、收据（重启即恢复） |
| `scheduler.json` | 调度器状态：今日计数、忽略连击、下次到期 |
| `ledger.json` | 主动交流账（`ProactiveLedgerBook`，与行为拦截账分开） |

## 8. 回合引擎（P1）

- **回合与拍数**（`rally.js`）：`rallyId`、`shot`（第几拍）、2 小时窗口、`rallyStats()`。"有效回合 = 至少两拍且有一拍接住了"。
- **六种发球**（`serve.js`，顺序即兜底顺序：前具体后轻）：`observe 观察` / `memory 记忆回调` / `provoke 观点挑衅` / `challenge 小挑战` / `chat 闲聊` / `review 复盘`。**最近三次用过的不再挑**；掷骰子用调用方传进来的 roll（0–100），纯本地不花模型。
- **判球**（`judge.js`）：六个判词 `engaged / brief / evasive / stock / refuse / pushback`；四种回击 `deeper / angle / callout / stop`；**6 秒超时**；连不上、超时、输出不是 JSON —— **一律退回本地规则**，绝不因为判球失败让一轮卡住（`judged:false` 如实记账）。
- **套话守卫**（`stock.js`）：模板套话相似度 ≥0.6 判定为套话。**能力边界**：球是 agent 在会话里写的，插件只在生成后看得到文本，没有"发布前改文本"的钩子——所以只能**记下来 + 下一球原句打回**，不假装重写过。
- **假用户测试**：`test/fake-user.test.mjs` 用"一直敷衍 / 一直套话 / 真反驳"三种人设跑，断言判词与回击类型。

## 9. 漠视阶梯与三个渠道（P2 + P4）

### 9.1 阶梯（`silence.js`）

| 到点 | 级别 | 动作 |
|---|---|---|
| 5 分钟 | `lighter` | 换更轻的球（只从 `challenge` / `chat` 里挑） |
| 15 分钟 | `channel` | **换渠道**：开着语音就念出来；没开就靠屏幕 |
| 连续 2 次没接 | `stop` | 本轮停下，把"几点、哪类球被漠视了"记下来，下次当素材 |

补充规则：每小时上限（默认 3）、每天上限（默认 6）、安静时段、`minGap`（默认 30 分钟）。**阶梯故意压过 `minGap`**——否则 30 分钟一卡，5 分钟那一级永远走不到；频率由每小时上限兜住。被漠视的类型降权、接住的升权（`serveWeights`）。

### 9.2 三个渠道的真实分工

| 渠道 | 实现 | 什么时候用 | 状态 |
|---|---|---|---|
| 通知 | `NotificationPortImpl` | 无障碍没连、或浮层失败退回 | 已有 |
| 浮层 | `ProactivePageActivity.start` | 无障碍连着时的默认首选 | 已有 |
| **语音（TTS）** | `TextSpeaker`（P4 新增） | **只在 15 分钟换渠道那一级，且他开了语音** | 本轮新写，未真机验证 |

**为什么语音必须能单独成立**：闸门里 `screen_off` / `locked` 会让 `surface()` 返回 null，于是**锁屏时连通知都不会发**，事件就一直在队列里等到他亮屏。而"被漠视 15 分钟后换个法子"要解决的恰恰是他把手机揣兜里/锁着屏的场景——那种场景下能到耳朵里的只有声音。所以 P4 的做法是加第三个渠道 `Surface.SPEECH`：它**无视灭屏/锁屏**，但仍然让开 DSH 自己在用屏幕的时刻。

### 9.3 "换渠道"里哪一半是真的新的

- 「通知 → 浮层」这半级**本来就已落地**：无障碍连着时手机侧首选就是浮层。所以没开语音时，15 分钟这一级在渠道上其实没有可换的东西（这也是 P2 当时只写意图的原因）。
- 真正新增的是**语音这条渠道**：`/plan` 回 `channel:"speech"` → 手机读它 → 用系统 TTS 念。

### 10.1 现存两套人格卡（这是当前最明显的一处浪费）

| **会不会进模型 prompt** | **不会**（代码里没有任何一处读它拼 prompt） | **会**（`personaLines()` 拼进每球 prompt） |

**A 的真机实际值（从模拟器 `relationship.db` 里读出来的，非推测）**：

```
non_negotiables:  不撒谎 / 不假装记得 / 不替你做决定

own_interests:    夜里读一点书
boundaries:       不陪你逃避已经约定的事 / 不在你明确说停后继续
version:          1        updated_by: system        updated_at: 2026-11-04T14:58:47.796Z
```

**结论**：A 是"存着但没用"的占位数据；B 是"通路通了但卡是空的"。所以现在大肥鱼的"人格"实际上只来自它那个 DSH 会话自带的 system prompt，两张卡都没在影响输出。

任务书 §6 写的是"人格卡存在 DSH 会话的人设里（DSH 本来就支持）"，而 P3 实际落在**插件配置**里——这两处不会互相同步，是已知的偏差。

### 10.2 两种模式

| | 伙伴 `partner` | 教练 `coach` |
|---|---|---|
| 发球偏好 | chat / memory / observe … | observe / provoke / challenge … |

**结构性缺口**
- 两套人格卡互不相通（§10.1）：一套存着没用，一套空着。
- 「通知 → 浮层」这半级早就默认成立，所以**没开语音时，15 分钟这一级在渠道上没有实质变化**。
- 判球失败一律退回规则，所以极端情况下判词是规则给的，不是模型给的（账本里 `judged:false` 可见）。
- 回合状态不另存盘，全从账本重建——账本被截断会丢回合上下文。

**环境风险（踩过的坑，别重试）**
- 手工发闹钟广播无效（返回 `result=0` 但 logcat 无 `DshProactive`）。
- release 包不可 `run-as`（`package not debuggable`）；arm64 包装进 x86_64 模拟器必崩。
- 设备时钟是 UTC/GMT（比主机慢 8 小时），账本 `at` 早于主机时刻**不是缺陷**。
- `BuiltinPluginGuest.writeFiles` 是"内容没变就不写"，必须让引擎真正重启才看得到新文件。
- 用 PowerShell 的 `>` 重定向取设备上的二进制（截图、sqlite）会写坏文件；要用 Git Bash 或 `cmd.exe` 重定向。

## 附：一句话记住每一层在干什么

- **companion** 决定"要不要开口、说什么、用什么球、什么渠道"；
- **App 内核** 决定"现在能不能开口、用哪个面呈现、他接没接"；
- **Dart** 只搬数据，一个决定都不做；
- **relationship** 记关系与承诺（人物卡目前没接上）；
- **memory** 是记忆权威，每轮取几条塞上下文；
- **mood** 让心情像活人一样涨落；
- **fish-strict** 是另一条独立的监督通道，不抢 companion 的活。
