## 一、项目定位与核心技术约束

1. **长期主线确立**：以我们的 `r4/main` 分支作为长期维护主线，后续所有新版本 APK 均在此分支直接构建发布，**禁止每次上游更新都重新从零迁移或重写**。
2. **纯真原则（禁止虚假 PASS）**：
   - 编译成功 != 功能验收成功。
   - 单元测试通过 != 生产路径生效（必须走真实装配入口，杜绝用测试私有构造掩盖未接线）。
   - 在真实设备跑通前，严禁宣称“真机端到端通过”。
3. **架构纪律**：
   - `loop/core` 为纯 Kotlin JVM 架构，严禁依赖 `android.*`，确保可在任何环境秒级无损回归。
   - 所有状态推进必须经由统一事务入口提交快照，严禁跨文件独立写入。

## 三、全历程演进复盘（从 1.0.4 起点到 R4 最新状态）

- **R3 发布点**：锁定 `bf01594`，建立了可对比历史。
- **R4 加固期 (ac04b38)**：并行推进 M1(行为拦截与题库抽查)、M2(插件生态与台账注册)、M3(人格记忆与情绪通道)。但彼时残留了大量未经验证的代码假定。

### 3.2 逻辑闭环期（推翻自证，正视真实缺陷）
在第三阶段中，团队实施严厉的逻辑闭环：
- **推翻自证谎言**：早期报告称“Schemastery 宿主已支持”，核查发现宿主根本没有 `globalThis.__dshSchemastery`，是测试手动注入造成的假象；改为使用原生 `createRequire` 同步加载宿主模块。
- **B 站真网络风控 Bug**：发现 `getJson` 遇到 412 时提前断定 `!res.ok` 而不读 body，导致匿名重试成为死代码；自造 UA 被风控，真机查询必然失败。均在此时彻底修复。
- **PRoot 孤儿文件丢失 Bug**：发现 PRoot decrement 非原子，被杀时会将唯一数据块当做孤儿误删，为此设计了严格的 `repair()`。
- **揭穿“970=970”假象**：证明全量 Flutter Widget 测试的失败计数会受系统调度与并发影响浮动，确立必须使用**双向集合差集**与单测重复采样来判定回归。

### 3.3 架构大修期 (Phase 4 / Phase 4B: 五大 P0 与崩溃一致性)
架构审查暴露了适配层生命周期的 5 大致命漏洞：
- **P0-1 (事件永久悬挂)**：启动被丢、配置变更、锁屏重入等导致 Activity 永不结算，守卫陷入 `already_open` 放行一切目标。设计 `InterceptDeadline` 独立判定算法，采用单调时钟 `mono()` 挂载截止定时器。
- **P0-2 (前台不重判)**：拦截结束后无障碍服务不重新检测前台，最近任务切回形成长驱直入。在所有结束路径中埋设 `recheckForeground`。
- **P0-3 (未展示仍扣额度)**：`NOT_SHOWN` 结局不回滚 Block 时盖下的 `lastTriggerAt` 与 `countToday`，导致启动失败反获 2 分钟放行。实现消费捕获与精准冲正。
- **P0-4 (跨文件写入分裂)**：`guard.json` 与 `ledger.json` 双文件独立提交，崩溃必定导致白名单与回执错位。确立单一原子快照 `intercept.snapshot.json`，设计 `InterceptRepository` 与 `InterceptMigration`。
- **P0-5 (未展示秒过训练)**：代码中 `shownAt != 0L && ...` 导致 `shownAt == 0` 时整段短路跳过停留检查。拦截门前置锁死 `openShownAt != 0L`。
- **D5 (伪造放行漏洞)**：原代码将 `cooldown` 和 `dailyMax` 算作 `Allow`，按退出可骗取 2 分钟免费时间。彻底切断技术降噪与访问许可的关联，除白名单、暂停、真放行、规则窗口外绝不产生 `Allow`。

### 3.4 严苛自审与生产补线 (W0–W4, F0–F7, G0–G3)
在随后自主执行的全面代码审查中，发现测试通过背后的严重接线断层并予以修复：

### 4.1 生产单入口：InterceptKernel 组合工厂
**源码位置**：`app/android/app/src/main/kotlin/io/github/ccch1mneyyy/dsh_app/loop/core/InterceptKernel.kt:31-78`
```kotlin
object InterceptKernel {
    class Opened(
        val guard: InterceptGuard,
        val ledger: InterceptLedgerBook,
        val repo: InterceptRepository?,
        val migration: InterceptMigration.Result,
    )

    fun open(
        dir: File,
        clock: () -> Long,
        ids: () -> String,
        snapshotStore: (File) -> SnapshotStore = { AtomicJsonFile(it) },
    ): Opened {
        val snapshot = snapshotStore(File(dir, InterceptRepository.FILE_NAME))
        val legacyGuard = File(dir, "guard.json").let { if (it.exists()) AtomicJsonFile(it) else null }
        val legacyLedger = File(dir, "ledger.json").let { if (it.exists()) AtomicJsonFile(it) else null }

        val migration = InterceptMigration.run(snapshot, legacyGuard, legacyLedger)

        return when (migration) {
            is InterceptMigration.Result.RecoveryRequired -> legacyFallback(dir, clock, ids, migration)
            else -> onSnapshot(snapshot, clock, ids, migration)
        }
    }
}
```
*设计要点*：顺序锁死，迁移先行；快照视图注入账本；Guard 持有统一 Repo。若迁移发现旧数据冲突，自动降级为双文件隔离只读保护，绝不伪造或删除用户数据。

### 4.2 崩溃原子性：InterceptRepository 提交协议
**源码位置**：`app/android/app/src/main/kotlin/io/github/ccch1mneyyy/dsh_app/loop/core/InterceptRepository.kt:101-160`
```kotlin
fun commit(
    config: Map<String, Any?>,
    guardState: Map<String, Any?>,
    ledgerState: Map<String, Any?>,
    appliedEventIds: List<String>,
): Boolean {
    val next = Snapshot(
        schemaVersion = SCHEMA,
        config = config,
        guardState = guardState,
        ledgerState = ledgerState,
        appliedEventIds = appliedEventIds,
        lastCommittedTransactionId = transactions + 1,
    )
    val problem = validate(next)
    if (problem != null) {
        lastCommitError = problem
        return false
    }
    return try {
        store.write(next.toMap()) // 临时文件 -> flush -> fsync -> 原子重命名 -> 目录 fsync
        val readBack = store.read()
        val landed = when (readBack) {
            is SnapshotStore.Read.Loaded -> Snapshot.fromMap(readBack.map)
            else -> { lastCommitError = "commit read-back failed"; return false }
        }
        // 比对序列化文本，避免 JSON 数字装箱类型 (Int vs Long) 干扰
        if (Json.write(next.toMap()) != Json.write(landed.toMap())) {
            lastCommitError = "commit read-back differs from what was written"
            return false
        }
        // 唯有落盘且回读一致，内存指针方可向前跃迁
        committed = next
        transactions = next.lastCommittedTransactionId
        lastCommitError = null
        true
    } catch (t: Throwable) {
        lastCommitError = "${t.javaClass.simpleName}: ${t.message}".take(300)
        false
    }
}
```

### 4.3 内存回滚：transact 事务防护与扣额安全
**源码位置**：`app/android/app/src/main/kotlin/io/github/ccch1mneyyy/dsh_app/loop/core/Intercept.kt:835-865`
```kotlin
private fun transact(block: () -> Boolean): Boolean {
    val repo = repository ?: run {
        val ok = block()
        if (ok) persist()
        return ok
    }
    val configBefore = config
    val stateBefore = state
    val ledgerBefore = ledger.state
    val appliedBefore = ledger.appliedIds()
    val chargedAtBefore = chargedLastTriggerAt
    val chargedPkgBefore = chargedLastTriggerPackage
    val chargedCountBefore = chargedCountToday

    val ok = block()
    if (!ok) return false
    persist()
    if (storageError == null) return true

    // 写盘失败：内存无条件还原，防止假性成功
    config = configBefore
    state = stateBefore
    ledger.restore(ledgerBefore, appliedBefore)
    chargedLastTriggerAt = chargedAtBefore
    chargedLastTriggerPackage = chargedPkgBefore
    chargedCountToday = chargedCountBefore
    return false
}
```

### 4.4 失败物理阻断：D2 降级链与 EnforcementAlert

```kotlin
private fun enforceLeave(packageName: String, code: String) {
    if (!goHome()) {
        reportEnforcementUnavailable(packageName, code, 0)
        return
    }
    main.postDelayed({
        val after = currentForeground()
        if (!EnforcementOutcome.stillInFront(after, packageName)) {
            recheckForeground("intercept_enforced_exit") // 目标已切走
            return@postDelayed
        }
        if (!goHome()) {
            reportEnforcementUnavailable(packageName, code, 1)
            return@postDelayed
        }
        main.postDelayed({
            val second = currentForeground()
            if (EnforcementOutcome.stillInFront(second, packageName)) {
                reportEnforcementUnavailable(packageName, code, 2, EnforcementOutcome.failureKind(second, packageName))
            } else {
                recheckForeground("intercept_enforced_exit")
            }
        }, HOME_RETRY_MS)
    }, HOME_RETRY_MS)
}
```

### 4.5 授权防伪：D5 纯净裁决函数
**源码位置**：`app/android/app/src/main/kotlin/io/github/ccch1mneyyy/dsh_app/loop/core/Intercept.kt:286-332`
```kotlin
fun decide(...): InterceptDecision {
    if (packageName.isNullOrBlank()) return InterceptDecision.Ignore
    val target = config.targetFor(packageName) ?: return InterceptDecision.Ignore
    if (!config.enabled) return InterceptDecision.Allow(packageName, REASON_DISABLED)
    if (packageName in config.whitelist) return InterceptDecision.Allow(packageName, REASON_WHITELIST)
    if (config.pauseUntilWall > now) return InterceptDecision.Allow(packageName, REASON_PAUSED)
    if (releasedUntilWall > now) return InterceptDecision.Allow(packageName, REASON_RELEASED)
    if (inAuthorizedWindow(config, env.minuteOfDay)) return InterceptDecision.Allow(packageName, REASON_AUTHORIZED_WINDOW)
    if (!env.screenOn) return InterceptDecision.Allow(packageName, REASON_SCREEN_OFF)
    if (!env.unlocked) return InterceptDecision.Allow(packageName, REASON_LOCKED)
    if (env.dshBusy) return InterceptDecision.Allow(packageName, REASON_DSH_BUSY)

    // D5: 达到每日上限或冷却中仅代表“抑制打扰”（Ignore），绝非“批准放行”
    if (config.dailyMax > 0 && countToday >= config.dailyMax) {
        return InterceptDecision.Ignore
    }
    if (lastTriggerPackage == packageName && lastTriggerAt != 0L && now - lastTriggerAt in 0 until config.cooldownMs) {
        return InterceptDecision.Ignore
    }
    return InterceptDecision.Block("", target, "target", InterceptDrill.NONE)
}
```

## 五、已知缺陷、未决技术债与环境局限

1. **proot 5.1.107.102 的 L2s 迁移实测缺失**：
   - 现状：由于 Termux 官方源强行下架了 `.101` 的 aarch64 deb 包，审查方在 CI 打包时直接升到了 `.102`。
   - 风险：虽然理论分析认为仅影响 proc 命名，但从源码构建二进制、在真实 `--link2symlink` 下验证布局的工作只做过 `.98` 和 `.101`，**.102 尚未在极端掉电场景实测过**。

   - 本机 adb 环境当前仅有一台 x86_64 架构模拟器 (`emulator-5554`)，缺乏真实 ARM64 实体机。
   - `device-smoke.md` 所列的 9 项验收用例尚未由物理手机完成真机打卡。
3. **P0-A (YishouProtocol) 需接入主动体系审计**：
   - 审查方新增的 Yishou 答题移交具备 15 项单测，但在真实多会话环境与主动交流竞争 ScreenSlot 的协调机制需在命令四中完成联动审计。
